# Strata

AR-ядро для iOS: наложение материалов на реальные поверхности (стены, пол, потолок),
сканирование и обмер комнаты. Лицензируемый B2B SDK.

Этот репозиторий — **бинарная дистрибуция** SDK: подключается через SPM и поставляет
скомпилированный `Strata.xcframework`. Исходники ядра сюда не входят.

## Требования

- iOS 17+
- Xcode 16+
- iPhone 12 Pro+ (LiDAR) — для функций RoomPlan-отделки и LiDAR-обмера комнаты.
  Остальное (детект поверхностей, наложение материалов, ручной обмер) работает без LiDAR.

## Установка (SPM)

Xcode → **File → Add Package Dependencies…** → вставить URL:

```
https://github.com/antyukhin/strata-dist
```

Выбрать правило версии **Up to Next Major** от `0.15.0` и добавить продукт `Strata` в таргет.

Или в `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/antyukhin/strata-dist", from: "0.15.0"),
],
targets: [
    .target(name: "MyApp", dependencies: ["Strata"]),
]
```

## Быстрый старт

```swift
import UIKit
import Strata

// 1. Описать материал из своего каталога (ядро каталог не знает)
struct MyTile: StrataMaterial {
    var id = "tile-white-60"
    var name = "Белая плитка 60×60"
    var textureURL = Bundle.main.url(forResource: "tile_white", withExtension: "jpg")!
    var physicalSize = CGSize(width: 0.6, height: 0.6) // реальный размер в метрах → тайлинг
    var roughness: Float = 0.3
    var metallic: Float = 0.0
}

final class ViewController: UIViewController, StrataDelegate {
    let session = StrataSession()

    override func viewDidLoad() {
        super.viewDidLoad()
        let arView = session.makeView()
        arView.frame = view.bounds
        arView.autoresizingMask = [.flexibleWidth, .flexibleHeight]
        view.addSubview(arView)
        session.delegate = self
        try? session.start()

        let tap = UITapGestureRecognizer(target: self, action: #selector(handleTap))
        arView.addGestureRecognizer(tap)
    }

    @objc func handleTap(_ g: UITapGestureRecognizer) {
        guard let surface = session.surface(at: g.location(in: g.view)) else { return }
        Task { try? await session.apply(MyTile(), to: surface.id) }
    }

    func strata(_ s: StrataSession, didDetect surface: DetectedSurface) {}
    func strata(_ s: StrataSession, didFailWith error: StrataError) {}
}
```

## Публичный API

| Тип | Назначение |
|-----|------------|
| `StrataSession` | Основная AR-сессия: детект поверхностей, наложение/смена материала |
| `StrataView` | RealityKit-вью сессии (`makeView()`) |
| `StrataMaterial` | Протокол материала — реализует клиент (id, текстура, `physicalSize`, PBR) |
| `StrataDelegate` | События сессии: обнаружение поверхности, применение, ошибки |
| `StrataDiagnostics` | Диагностика состояния AR-сессии |
| `StrataError` | Ошибки SDK |
| `StrataRoomSession` + `StrataRoomDelegate` | RoomPlan-отделка с окклюзией (LiDAR); USDZ-экспорт скана |
| `StrataMeasureSession` + `StrataMeasureDelegate` | Обмер комнаты: LiDAR-контур, ручная «рулетка» или контур стены (`.wall`); высота → 3D-модель комнаты; USDZ-экспорт скана |
| `MeasureGuideStyle` | Стиль AR-направляющих обмера (цвета линий/углов/подписей, толщина, радиус) |
| `Room3DModel` + `RoomMesh` | 3D-модель комнаты (пол/стены/потолок, проёмы) и её триангуляция; на LiDAR стены со скосом — реальной формы, стены ниши — своей высоты, устье ниши — отдельной гранью |
| `DetectedOpening` | Проём (дверь/окно) из LiDAR-скана: габарит, привязка к стене и положение на ней |

Полная документация по API, RoomPlan и обмеру — в основном репозитории ядра.

### Проём на стене (`DetectedOpening`)

`wallID` — **строковое представление индекса** wall-грани в `Room3DModel.faces`:
`model.faces[Int(opening.wallID)!]`. Это часть контракта, формат не изменится без
мажорной версии.

`originInWall: SIMD2<Float>?` — минимальный угол проёма в 2D-базисе той же грани
(метры). Базис — тот, которым построена сама грань, поэтому проём и контур стены
лежат в одной системе координат:

```swift
let face = model.faces[Int(opening.wallID)!]
let origin = model.vertices[face.vertices[0]]                 // начало базиса
let u = normalize(cross(SIMD3<Float>(0, 1, 0), face.normal))  // вдоль стены  → .x
let v = cross(face.normal, u)                                 // вверх в грани → .y

// контур самой грани — в тех же осях:
let contour = face.vertices.map { i -> SIMD2<Float> in
    let d = model.vertices[i] - origin
    return SIMD2(dot(d, u), dot(d, v))
}
// прямоугольник проёма: originInWall … originInWall + SIMD2(width, height)
```

Вертикаль приведена к полу `Room3DModel` (на LiDAR-пути — `y = 0`), а не к мировому
`y` скана. **Знак координат не гарантирован**: `u` выводится из нормали грани, а не из
порядка вершин, поэтому первая вершина может лежать правее или выше проёма — вычитайте
`originInWall` из контура грани, а не отсчитывайте «слева направо от нуля».
Проём привязывается только к грани, в габарит которой помещается (± 3 см, центр не
дальше 15 см от её плоскости); не поместившийся никуда в `openings` не попадает. Поэтому
у каждого возвращённого проёма `originInWall` задан; `nil` бывает только на ручном обмере,
где `openings` пуст.

## Changelog

### 0.15.0
- **Ниша в LiDAR-модели.** Стена скана, заметно (> 5 см) ниже комнаты и стоящая на полу
  (откосы и задняя стенка ниши), строится до своего верха, а не выдавливается на
  `height`.
- **Устье ниши — отдельная wall-грань** в конце `faces`: стена скана, которой нет в
  контуре пола. Шире: любая стена скана без пары в контуре (внутри контура пола или не
  дальше 0,10 м от него) — например, отдельно стоящая перегородка — теперь становится
  такой гранью; раньше она игнорировалась. Индексы прочих граней не меняются.
- **Проём — только на грани, в которую помещается.** Раньше устье ниши садилось на
  соседнюю стену той же плоскости с `originInWall` за её краем. ⚠️ Изменение поведения:
  проём, не поместившийся ни в одну грань, **больше не возвращается**.
- Нормали стен ориентируются по обходу контура пола — на невыпуклом полу (ниша, Г-образная
  прихожая) часть стен раньше смотрела наружу. Контуры стен выравниваются по полу скана.
- Потолок над нишей по-прежнему синтетический и неверен; модель с нишей не замкнута.
- Публичный API не изменился. Проверено на реальных сканах (тесты на фикстурах);
  живой прогон на устройстве — не пройден.

### 0.14.0
- **Положение проёма на стене.** `DetectedOpening.originInWall: SIMD2<Float>?` —
  минимальный угол проёма в 2D-базисе грани, к которой он привязан (обе координаты,
  метры). Раньше у проёма была только горизонталь, и высоту нижней кромки восстановить
  было не из чего: проём без обеих координат нельзя ни вычесть из площади полосой, ни
  обойти раскладкой плитки. Базис и оговорки — в разделе «Проём на стене» выше.
- Вертикаль приводится к полу модели: скан живёт в мировых координатах ARKit (пол
  ≈ −1.4 м), пол `Room3DModel` на LiDAR — на `y = 0`.
- `originInWall` заполняется только по строгой (компланарной) привязке к стене. На косой
  привязке проекция схлопывает габарит вдоль `u`, поэтому отдаётся `nil`: неизвестное
  положение представимо, неверное — нет.
- `DetectedOpening.offsetAlongWall` — **deprecated** в пользу `originInWall` (другое
  начало отсчёта и нет вертикали). Продолжает заполняться, JSON-ключ прежний.
- Формат `wallID` (строковый индекс грани в `Room3DModel.faces`) зафиксирован как контракт.
- Аддитивно, ломающих изменений нет: поле опциональное, старый JSON декодируется.
- ⚠️ Приёмка на устройстве не пройдена: непустой `Room3DModel.openings` на реальном скане
  с дверью и окном не подтверждён. Покрыта юнит-тестами геометрия, не RoomPlan-данные.

### 0.13.0
- **Реальная форма стен на LiDAR.** Стена со скошенным верхом (мансарда, односкатный
  потолок) строится из `CapturedRoom.Surface.polygonCorners`, а не выдавленным
  прямоугольником: `Room3DModel.Face.vertices` — контур произвольной длины. Контур
  используется, только если по форме он не прямоугольник; обычная комната строится
  как раньше.
- `Room3DModel.Face.isSynthesized` — грань достроена допущением (потолок всегда;
  стена, выдавленная из ребра пола), а не измерена. У комнаты со скосом настоящий
  потолок — скат, поэтому площадь синтезированного потолка по такому скану неверна:
  теперь это видно из данных. JSON моделей до 0.13.0 декодируется (дефолт `false`).
- Зафиксирован **контракт грани**: `Face.normal` единичная и направлена внутрь комнаты;
  оси в плоскости грани строить от неё (`u = normalize(cross(worldUp, face.normal))`),
  а не от порядка вершин — winding не гарантирован. У вырожденной грани нормаль нулевая.
- `DetectedOpening.offsetAlongWall` считается вдоль той же оси `u` от вершины стены с
  минимальной проекцией на неё: значение неотрицательно и не больше длины стены.
- `Room3DModel.height` на LiDAR — максимум по стенам скана (высота самой высокой стены).
- Аддитивно, ломающих изменений нет.

## Выпуск нового релиза (для мейнтейнера)

Порядок важен: тег этого репо — это то, что разрешает SPM, и он обязан указывать на
коммит с уже обновлённым `checksum`. Поэтому тег создаётся **последним**, а не
переставляется силой: `git push -f` по существующему тегу не дойдёт до тех, кто эту
версию уже разрешил — у них останется закешированный старый `Package.swift`.
Так был выпущен битый 0.14.0.

1. В репозитории **ядра** собрать ассет и получить checksum (без публикации):
   ```bash
   ./build-xcframework.sh --zip
   ```
2. В этом репо обновить `url` (на тег `X.Y.Z`) и `checksum` в `Package.swift`, добавить
   запись в changelog README.
3. Закоммитить и запушить — тега ещё нет, ссылка в `Package.swift` пока битая:
   ```bash
   git commit -am "release: Strata X.Y.Z binary (checksum)"
   git push origin main
   ```
4. Создать релиз: он тегает свежий HEAD и заливает ассет по тому самому URL.
   ```bash
   gh release create X.Y.Z ../Strata/build/Strata.xcframework.zip \
     --repo antyukhin/strata-dist --title X.Y.Z --generate-notes
   ```
5. Проверить, что тег и ассет сошлись:
   ```bash
   gh release view X.Y.Z --repo antyukhin/strata-dist
   curl -sL <url из Package.swift> -o /tmp/s.zip && swift package compute-checksum /tmp/s.zip
   ```
   Чексумма обязана совпасть с той, что в `Package.swift` на теге `X.Y.Z`.

> `./build-xcframework.sh --release X.Y.Z` из ядра делает шаги 1 и 4 одним вызовом, но
> тегает HEAD дистрибутива **до** коммита с checksum — это и есть та ловушка. Годится,
> только если следом обязательно выполнить шаги 2–3 и переставить тег.
